# ขอบเขตความปลอดภัยคือวง LAN ของสำนักงาน และยอมรับ HTTP เปล่า

ระบบนี้เคยเปิดให้ทุกเครื่องในวง LAN เข้าถึงได้ (`run_server.bat` ตั้ง `HR_HOST=0.0.0.0`)
โดยไม่มีการล็อกอินเลย ใครที่เข้าถึงพอร์ต 5000 ได้ก็อ่าน แก้ และลบข้อมูลการเลื่อนระดับของ
ทุกคนได้ รวมถึง `DELETE /api/records` ที่ล้างทั้งฐาน การเพิ่มระบบล็อกอินจึงเป็นการปิดรูนั้น

ภัยที่ระบบนี้ตั้งใจกัน: **คนในวง LAN เดียวกันที่ไม่ควรเห็นข้อมูลนี้** ข้อมูลผลประเมินและ
คะแนนของเพื่อนร่วมงานเป็นข้อมูลอ่อนไหว คนที่ไม่ได้รับบัญชีต้องเข้าไม่ถึงเลย ไม่ใช่แค่
"กันคนกดพลาด"

ภัยที่ระบบนี้ **ไม่** ได้กัน: ผู้โจมตีจากอินเทอร์เน็ต — ระบบไม่ได้เปิดออกไป และการดักฟัง
ทราฟฟิกภายในวง LAN

## การยอมรับ HTTP เปล่า

ระบบวิ่งบน HTTP ไม่มี TLS รหัสผ่านตอนล็อกอินและ cookie ของเซสชันจึงวิ่งเป็นข้อความอ่านได้
ใครที่ดักจับทราฟฟิกในวงได้ (เช่น เครื่องบน Wi-Fi เดียวกัน) เห็นรหัสผ่านของคนที่กำลังล็อกอิน
นี่คือข้อจำกัดที่ขัดกับภัยที่ตั้งใจกันข้างบนตรง ๆ และเรารู้ตัว

ทางเลือกที่พิจารณาแล้วไม่เลือก:

**ใบรับรองที่เซ็นเอง (self-signed)** ได้การเข้ารหัสมา แต่ทุกเครื่องจะเจอหน้าเตือนสีแดงของ
เบราว์เซอร์ทุกครั้ง และต้องสอนคนทั้งสำนักงานให้กด "ไปต่อ" ผ่านคำเตือนความปลอดภัย ซึ่งเป็น
นิสัยที่ติดตัวไปใช้กับคำเตือนจริงในอนาคตด้วย ประเมินแล้วว่าขาดทุน

**Local CA (เช่น mkcert)** ได้ TLS จริงไม่มีคำเตือน แต่ต้องเดินไปติดตั้ง root CA ที่ทุกเครื่อง
ด้วยมือ และต่ออายุใบรับรองเองเป็นระยะ เป็นงานดูแลต่อเนื่องที่หน่วยงานนี้ไม่มีคนรับไป ระบบที่
พังเพราะใบรับรองหมดอายุแล้วไม่มีใครรู้วิธีต่อ แย่กว่าระบบที่ไม่เคยมี TLS

จึงยอมรับ HTTP เปล่าเป็นข้อจำกัดที่รู้ตัว **ไม่ใช่สิ่งที่มองข้าม** และบันทึกเงื่อนไขไว้ว่า:
**วันที่ระบบนี้จะเข้าถึงได้จากนอกวง LAN คือวันที่เอกสารนี้ต้องถูกรื้อก่อนทำอย่างอื่น**

## Consequences

**cookie ของเซสชันไม่ตั้ง `Secure`** ถ้าตั้ง เบราว์เซอร์จะไม่ส่ง cookie บน HTTP เลยและ
ล็อกอินจะไม่ติดทั้งระบบ วันที่ย้ายไป HTTPS ต้องกลับมาตั้งที่ `_set_session_cookie()`

**`SameSite=Lax` เป็นเกราะ CSRF ตัวเดียวที่มี** ไม่มี CSRF token ในระบบนี้ เพราะ `Lax` ทำให้
เบราว์เซอร์ไม่แนบ cookie ไปกับ request ข้ามเว็บที่เป็น POST อยู่แล้ว ช่องที่จะเปิดถ้าใครแก้เป็น
`None` คือ POST อัปโหลดไฟล์แบบ multipart ซึ่งเว็บอื่นสั่งเบราว์เซอร์ของคนในสำนักงานยิงมาได้
โดยไม่ต้องผ่าน preflight ของเบราว์เซอร์ก่อน (ต่างจาก PUT/DELETE และ POST ที่เป็น JSON)

**บัญชีแรกสร้างได้ที่เครื่องเซิร์ฟเวอร์เท่านั้น** ผ่าน `manage_users.py` หน้า "สร้างผู้ดูแลคนแรก"
บนเว็บจะเป็น endpoint ที่เขียนข้อมูลได้โดยไม่ต้องล็อกอิน เปิดอยู่บนพอร์ตที่ทั้งวงเข้าถึง และมัน
จะกลับมาเปิดอีกทุกครั้งที่ตาราง `users` ว่าง — รวมถึงตอน restore สำเนาสำรองผิดไฟล์ ใครในวง
ที่เปิดหน้านั้นทันก่อนเจ้าของระบบก็ได้เป็นผู้ดูแล

**ตาราง `users` ที่ว่างแปลว่าไม่มีใครเข้าได้ ไม่ใช่ไม่ต้องล็อกอิน** รวมถึงเจ้าของระบบเอง
หน้าล็อกอินจะบอกคำสั่งที่ต้องไปรันที่เครื่องเซิร์ฟเวอร์ แต่ไม่มีทางลัดให้จากหน้านั้น

**การดักฟังในวงยังเป็นช่องที่เปิดอยู่** ถ้าวันหนึ่งประเมินว่าภัยนี้เกิดขึ้นได้จริงในที่ทำงานนั้น
ทางแก้คือ local CA ตามข้างบน ไม่ใช่ self-signed
