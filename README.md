# ระบบบันทึกข้อมูลบุคคลและประเมินผลงานเพื่อเลื่อนระดับตำแหน่ง

โปรแกรมเดสก์ท็อปสำหรับบันทึกข้อมูลผู้ขอรับการประเมิน เก็บเล่มผลงาน (PDF) บันทึกคะแนนประเมิน
และสรุปภาพรวมเป็นกราฟ ออกแบบให้**ทำงานได้โดยไม่ต้องต่ออินเทอร์เน็ต** และแพ็กเป็นไฟล์ `.exe`
ไฟล์เดียวแจกให้เครื่องในหน่วยงานใช้

Flask + SQLite3 + pywebview — ข้อมูลทั้งหมดอยู่บนเครื่องผู้ใช้ ไม่มีการส่งออกไปที่ไหน

---

## คุณสมบัติ

- **ฟอร์มบันทึกข้อมูล 6 ส่วน** — ข้อมูลส่วนตัว, ตำแหน่งปัจจุบัน, ตำแหน่งที่ขอประเมิน (พร้อมไฟล์ประกาศ),
  ผลงานที่เสนอ, ผลการประเมิน (รวมตารางคะแนน 5.1 / 5.2 แบบเพิ่ม-ลบแถวได้), และไฟล์เล่มผลงาน
- **แนบไฟล์ PDF** ได้ 4 ช่องต่อหนึ่งรายการ — เล่มผลงาน 1-3 และไฟล์ประกาศ ดูในเบราว์เซอร์หรือดาวน์โหลดได้
- **รายการทั้งหมด** — ค้นหาแบบพิมพ์แล้วกรองทันที (ชื่อ ตำแหน่ง หน่วยงาน ตำแหน่งเลขที่) แก้ไข ลบ
  และดูสถานะไฟล์แนบของแต่ละรายการ
- **สรุปภาพรวม** — กราฟ 4 ตัว: ผลการพิจารณาผลงาน, จำนวนตามระดับตำแหน่ง,
  จำนวนตามสำนัก/กอง/ศูนย์ และคะแนนประเมิน
- **ออกรายงาน** — พิมพ์/บันทึกเป็น PDF รายบุคคล และ export ทั้งระบบเป็น CSV (มี BOM เปิดใน Excel
  ภาษาไทยไม่เพี้ยน) หรือ JSON
- **ทำงานออฟไลน์ 100%** — Bootstrap, Chart.js, Font Awesome และฟอนต์ Sarabun เก็บไว้ใน
  `static/vendor/` ไม่มีการเรียก CDN ภายนอกเลย

## ความต้องการระบบ

| สิ่งที่ต้องมี | เวอร์ชันที่ทดสอบแล้ว |
|---|---|
| Python | 3.14.7 |
| Flask | 3.1.3 (pin ไว้ใน `requirements.txt`) |
| pywebview | 6.2.1 — ถ้าไม่มี โปรแกรมจะ fallback ไปรันเป็น web server ให้เปิดผ่านเบราว์เซอร์ |
| ระบบปฏิบัติการ | Windows 11 (ผู้ใช้ปลายทางใช้ `.exe` ไม่ต้องติดตั้ง Python) |

## ติดตั้งและรัน

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python app.py
```

- **มี pywebview** → เปิดเป็นหน้าต่างโปรแกรมปกติ
- **ไม่มี pywebview** → รันเป็น web server เปิด <http://127.0.0.1:5000> ในเบราว์เซอร์เอง

ทั้งสองโหมดผูกที่ `127.0.0.1` เท่านั้น เครื่องอื่นในเครือข่ายเข้าถึงไม่ได้ (ดูหัวข้อ
[ความปลอดภัย](#ความปลอดภัยที่ควรรู้))

## โหมดการทำงาน

หน้าเว็บตรวจเองตอนเปิดว่าคุยกับ Flask ได้หรือไม่ แล้วแสดงสถานะที่ badge มุมขวาบน

| โหมด | เงื่อนไข | ข้อมูลเก็บที่ | ไฟล์แนบ |
|---|---|---|---|
| **Flask + SQLite** | รันผ่าน `python app.py` หรือ `.exe` | `hr_promotion.db` | ใช้งานได้ครบ |
| **LocalStorage (Offline)** | เปิดไฟล์ HTML ตรง ๆ โดยไม่มี backend | LocalStorage ของเบราว์เซอร์ | **ไม่รองรับ** |

โหมด LocalStorage มีไว้เป็นทางหนีทีไล่เท่านั้น การใช้งานจริงควรใช้โหมด Flask

## ข้อมูลและไฟล์

| สิ่งที่เก็บ | ที่อยู่ |
|---|---|
| ฐานข้อมูล | `hr_promotion.db` (SQLite, โหมด WAL) อยู่ข้างตัว `app.py` หรือข้างตัว `.exe` |
| ไฟล์ PDF ที่อัปโหลด | `static/uploads/<uuid>.pdf` — ชื่อไฟล์บนดิสก์เป็น UUID ชื่อจริงเก็บใน DB |

**การสำรองข้อมูล** คัดลอก `hr_promotion.db` พร้อมโฟลเดอร์ `static/uploads/` ไปทั้งคู่
ทั้งสองอย่างต้องไปด้วยกัน เพราะ DB เก็บแค่ชื่อไฟล์ ไม่ได้เก็บตัวไฟล์

ฟิลด์ที่ server บังคับว่าต้องกรอก: ชื่อ, นามสกุล, ตำแหน่งปัจจุบัน, ตำแหน่งเลขที่
(ฟอร์มฝั่งหน้าเว็บบังคับมากกว่านี้)

## เงื่อนไขการอัปโหลดไฟล์

server ตรวจทุกไฟล์ก่อนเขียนลงดิสก์ — ไม่เชื่อการตรวจฝั่งหน้าเว็บ เพราะยิง API ตรงข้ามด่านนั้นได้

| เงื่อนไข | ถ้าไม่ผ่าน |
|---|---|
| ต้องไม่เป็นไฟล์ว่าง | `400` |
| ต้องมี header `%PDF-` ใน 1024 ไบต์แรก | `400` |
| ขนาดไม่เกิน 100 MB | `413` |
| ต้องมี record นั้นอยู่จริง | `404` |

อัปโหลดซ้ำช่องเดิมเป็นการ **แทนที่** ไฟล์เก่า (1 รายการมีไฟล์ได้ช่องละ 1 ไฟล์)

```
hr_promotion/
├── app.py                  Flask backend ทั้งหมด (routes + DB + migration)
├── templates/index.html    หน้าเว็บทั้งหน้า (HTML + CSS + JS ในไฟล์เดียว)
├── static/
│   ├── vendor/             Bootstrap, Chart.js, Font Awesome, Sarabun (self-hosted)
│   └── uploads/            ไฟล์ PDF ที่ผู้ใช้อัปโหลด
├── tests/                  ชุด pytest
├── check_db.py             ตรวจ schema ของ DB
├── fix_db.py               ซ่อมคอลัมน์ NOT NULL ที่ไม่มี DEFAULT
├── requirements.txt        dependency ของ runtime (pin ==)
└── requirements-dev.txt    เครื่องมือตอนพัฒนา (pytest)
```

## API

ทุก endpoint ตอบเป็น JSON ภาษาไทยอ่านออกตรง ๆ (ไม่ escape เป็น `\uXXXX`)

| Method | URL | ทำอะไร |
|---|---|---|
| GET | `/api/records` | รายการทั้งหมด (ใหม่สุดก่อน) |
| GET | `/api/records/<id>` | รายการเดียว |
| POST | `/api/records` | สร้างรายการใหม่ |
| PUT | `/api/records/<id>` | แก้ไขรายการ (ทับทุกคอลัมน์) |
| DELETE | `/api/records/<id>` | ลบรายการ + ไฟล์แนบทั้งหมด |
| DELETE | `/api/records` | ลบทั้งระบบ |
| GET | `/api/records/<id>/attachments` | รายการไฟล์แนบ (metadata) |
| POST | `/api/records/<id>/attachments` | อัปโหลด PDF (multipart หรือ base64-in-JSON) |
| GET | `/api/attachments/<att_id>` | ดาวน์โหลดไฟล์ |
| GET | `/api/attachments/<att_id>/preview` | เปิดดูไฟล์ในเบราว์เซอร์ |
| DELETE | `/api/attachments/<att_id>` | ลบไฟล์แนบ |
| GET | `/api/stats` | ยอดรวมแยกตามผลการประเมินและระดับตำแหน่ง |
| GET | `/api/export/csv` | export CSV (UTF-8 BOM) |

รายละเอียด schema และหมายเหตุสำหรับคนที่จะแก้โค้ดอยู่ใน [CLAUDE.md](CLAUDE.md)

## การทดสอบ

```bash
pip install -r requirements-dev.txt
python -m pytest
```

38 test รันจบใน ~0.7 วินาที ครอบการจัดการชื่อไฟล์ภาษาไทย, ลำดับการลบไฟล์เทียบกับ `commit`
(ทดสอบด้วยการจำลองให้ DB ล้มกลางทาง), การตรวจไฟล์อัปโหลด และ JSON ภาษาไทย

test ทุกตัวใช้ DB กับโฟลเดอร์อัปโหลดชั่วคราวของ pytest — **ไม่แตะ `hr_promotion.db` ของจริง**

## Build เป็น `.exe`

```bash
pyinstaller --onefile --noconsole ^
  --add-data "templates;templates" ^
  --add-data "static/vendor;static/vendor" ^
  app.py
```

`--add-data "static/vendor;static/vendor"` **ห้ามลืม** ไม่งั้น `.exe` จะหาไลบรารีไม่เจอ
หน้าเว็บจะเพี้ยนและกราฟไม่ขึ้น ส่วน `hr_promotion.db` กับ `static/uploads/` จะถูกสร้างข้างตัว `.exe`
เองตอนรันครั้งแรก

## ความปลอดภัยที่ควรรู้

- **ไม่มีระบบ login** โปรแกรมออกแบบมาให้ใช้บนเครื่องส่วนตัวของเจ้าหน้าที่ ใครเปิดเครื่องได้คือเห็นข้อมูลได้
  จึงผูก server ไว้ที่ `127.0.0.1` เท่านั้น **อย่าแก้ให้ผูก `0.0.0.0`** เพราะเท่ากับเปิดข้อมูลบุคคล
  ให้ทุกเครื่องในเครือข่ายอ่านและลบได้
- โหมด debug ปิดเป็นค่าเริ่มต้น เปิดได้ด้วย `HR_DEBUG=1` **สำหรับตอนพัฒนาเท่านั้น** เพราะ debugger
  ของ Werkzeug รันคำสั่ง Python จากเบราว์เซอร์ได้
- ไฟล์ `hr_promotion.db` และไฟล์ใน `static/uploads/` ไม่ได้เข้ารหัส และถูกตั้งไม่ให้ commit ขึ้น git
  (ดู `.gitignore`)
