# เข้าโหมดออฟไลน์เฉพาะเมื่อไม่มี backend อยู่จริง ไม่ใช่ตอน backend ล้ม

Frontend ตรวจว่ามี Flask backend ไหมด้วยการยิง `GET /api/records` หนึ่งครั้งตอนโหลดหน้า
เดิมใช้ `catch` ตัวเดียวครอบ แล้วถือว่า "ล้มเหลวด้วยเหตุใดก็ตาม" คือสัญญาณให้เข้าโหมดออฟไลน์
ผลคือเวลา backend ตอบ `500` (เช่น DB ถูกล็อกหรือไฟล์เสีย) ระบบสลับไปอ่าน LocalStorage
ที่ว่างเปล่า แล้วรายงานว่า "0 รายการ" ทั้งที่ข้อมูลใน SQLite ยังอยู่ครบ — เอาที่เก็บผิดอันมาตอบ
คำถามแล้วให้คำตอบที่ดูเหมือนข้อมูลหายไปหมด

จึงแยกความล้มเหลวเป็นสองอย่าง: `fetch` ที่ reject เอง (ไม่มี HTTP status) คือ **ไม่มี backend**
และเป็นเงื่อนไขเดียวที่เข้าโหมดออฟไลน์ ส่วนการตอบกลับที่มี status คือ **backend ล้ม** ซึ่งอยู่
โหมดปกติต่อแล้วรายงานเป็นความผิดพลาด

## Considered Options

ทางเลือกที่ไม่เลือก: ให้โหมดออฟไลน์ทำหน้าที่เป็นที่พึ่งเวลา backend มีปัญหาด้วย เพื่อให้ผู้ใช้
กรอกข้อมูลต่อได้ไม่สะดุด ไม่เลือกเพราะข้อมูลที่กรอกจะไปอยู่ใน LocalStorage ของเครื่องนั้น
แยกจาก SQLite โดยไม่มีกลไกรวมกลับ และผู้ใช้ไม่มีทางรู้ว่างานที่เพิ่งพิมพ์ไปอยู่คนละที่กับงานเก่า
ความสะดวกชั่วคราวจึงแลกมาด้วยข้อมูลสองชุดที่ไม่มีใครรวมได้

## Consequences

โหมดออฟไลน์เหลือความหมายเดียวคือ "ไม่มี backend" ตามชื่อ ใครที่เห็น `catch` สองสายใน
`detectMode` แล้วคิดจะรวบเป็นสายเดียวเพื่อความเรียบง่าย กำลังจะพาบั๊กนี้กลับมาทั้งดุ้น
เทสต์ที่ปักหมุดเรื่องนี้อยู่ใน `tests/client.test.mjs` หัวข้อ "นโยบาย fallback"
