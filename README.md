# ระบบบันทึกข้อมูลบุคคลและประเมินผลงานเพื่อเลื่อนระดับตำแหน่ง

โปรแกรมเดสก์ท็อปสำหรับบันทึกข้อมูลผู้ขอรับการประเมิน เก็บเล่มผลงาน (PDF) บันทึกคะแนนประเมิน
และสรุปภาพรวมเป็นกราฟ ออกแบบให้**ทำงานได้โดยไม่ต้องต่ออินเทอร์เน็ต** และแพ็กเป็นไฟล์ `.exe`
ไฟล์เดียวแจกให้เครื่องในหน่วยงานใช้

Flask + SQLite3 + pywebview — ข้อมูลทั้งหมดอยู่บนเครื่องผู้ใช้ ไม่มีการส่งออกไปที่ไหน

---

## คุณสมบัติ

- **ฟอร์มบันทึกข้อมูล 6 ส่วน** — ข้อมูลส่วนตัว, ตำแหน่งปัจจุบัน, ตำแหน่งที่ขอประเมิน (พร้อมไฟล์ประกาศ),
  ผลงานที่เสนอ, ผลการประเมิน (รวมตารางคะแนน 5.1 / 5.2 แบบเพิ่ม-ลบแถวได้), และไฟล์เล่มผลงาน
- **แนบไฟล์ PDF** ได้ 4 ช่องต่อหนึ่งรายการ — เล่มผลงาน 1-3 และไฟล์ประกาศ ดูในเบราว์เซอร์หรือดาวน์โหลดได้
- **รายการทั้งหมด** — ค้นหาแบบพิมพ์แล้วกรองทันที (ชื่อ ตำแหน่ง หน่วยงาน ตำแหน่งเลขที่) แก้ไข ลบ
  และดูสถานะไฟล์แนบของแต่ละรายการ
- **สรุปภาพรวม** — กราฟ 4 ตัว: ผลการพิจารณาผลงาน, จำนวนตามระดับตำแหน่ง,
  จำนวนตามสำนัก/กอง/ศูนย์ และคะแนนประเมิน
- **ออกรายงาน** — พิมพ์/บันทึกเป็น PDF รายบุคคล และ export ทั้งระบบเป็น CSV (มี BOM เปิดใน Excel
  ภาษาไทยไม่เพี้ยน) หรือ JSON
- **ทำงานออฟไลน์ 100%** — Bootstrap, Chart.js, Font Awesome และฟอนต์ Sarabun เก็บไว้ใน
  `static/vendor/` ไม่มีการเรียก CDN ภายนอกเลย
- **เข้าสู่ระบบด้วยบัญชีรายบุคคล** — ทุกหน้าและทุก API ต้องล็อกอิน มีสองบทบาท (ผู้ดูแลระบบ /
  เจ้าหน้าที่) และบันทึกไว้ว่าใครเพิ่ม แก้ หรือลบอะไร เปิดให้ทั้งวง LAN ใช้ร่วมกันได้ด้วย
  `run_server.bat`

## ติดตั้งและรัน

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python manage_users.py add somchai --role admin    # ครั้งแรกเท่านั้น
python app.py
```

**ต้องสร้างบัญชีก่อนเปิดโปรแกรมครั้งแรก** ทุกหน้าและทุก API ต้องล็อกอิน ถ้ายังไม่มีบัญชี
จะไม่มีใครเข้าได้เลยรวมถึงเจ้าของเครื่อง (หน้าล็อกอินจะบอกคำสั่งนี้ไว้ให้) คำสั่งจะถาม
รหัสผ่านทางหน้าจอ ไม่ต้องพิมพ์ต่อท้ายคำสั่ง

- **มี pywebview** → เปิดเป็นหน้าต่างโปรแกรมปกติ
- **ไม่มี pywebview** → รันเป็น web server เปิด <http://127.0.0.1:5000> ในเบราว์เซอร์เอง

### ไฟล์เปิดโปรแกรม

| ไฟล์ | เปิดแบบไหน | เครื่องอื่นเข้าได้ |
|---|---|---|
| `run.bat` | หน้าต่างโปรแกรม (pywebview) | ไม่ได้ |
| `run_browser.bat` | เบราว์เซอร์ บนเครื่องนี้ | ไม่ได้ |
| `run_server.bat` | เบราว์เซอร์ เปิดให้ทั้งวง LAN (`HR_HOST=0.0.0.0`) | ได้ |

### จัดการบัญชีผู้ใช้

ทำที่เครื่องที่เป็นเซิร์ฟเวอร์เท่านั้น ไม่มีหน้าจอจัดการผู้ใช้บนเว็บ

```bash
python manage_users.py list                     # ดูทั้งหมด + ใครล็อกอินค้างกี่เครื่อง
python manage_users.py add nipaporn.k           # เพิ่ม (ค่าเริ่มต้นบทบาท staff)
python manage_users.py passwd nipaporn.k        # ตั้งรหัสใหม่ + ไล่ออกทุกเครื่อง
python manage_users.py role nipaporn.k admin    # เปลี่ยนบทบาท
python manage_users.py disable nipaporn.k       # คนลาออก — ตัดทันที (ไม่มีคำสั่งลบบัญชี)
python manage_users.py logout-all nipaporn.k    # ไล่ออกทุกเครื่อง ไม่แตะรหัสผ่าน
```

ผู้ใช้เปลี่ยนรหัสผ่านของตัวเองได้จากปุ่มกุญแจบนหัวหน้าจอ

### แนวทางกำหนดบทบาท

**บทบาทต่างกันสองเรื่อง** เรื่องแรกคือปุ่ม **"ลบทั้งหมด"** (ล้างทุกรายการพร้อมไฟล์แนบ
ทั้งระบบ) ซึ่งเป็นของ `admin` เท่านั้น — staff ยังลบรายการทีละอันและลบไฟล์แนบได้ตามปกติ
เรื่องที่สองคือการจัดการบัญชี ซึ่งคุมด้วย**อันดับ** ไม่ใช่ด้วยการเปิดปิดทั้งหน้าจอ:

| การกระทำ | `admin` | `staff` |
|---|---|---|
| ดูรายชื่อบัญชีทั้งหมด | ได้ | ได้ |
| สร้างบัญชี | ได้ทุกบทบาท | ได้เฉพาะบทบาท `staff` |
| แก้ชื่อ-นามสกุล | ได้ทุกบัญชี | ได้เฉพาะบัญชี `staff` |
| ตั้งรหัสผ่านใหม่ให้คนอื่น | ได้ทุกบัญชี | ได้เฉพาะบัญชี `staff` |
| เปลี่ยนบทบาท | ได้ | ไม่ได้ |
| ปิดหรือเปิดบัญชี | ได้ | ไม่ได้ |

กฎเดียวที่อยู่เบื้องหลังตารางนี้คือ **ห้ามมอบบทบาทที่สูงกว่าของตัวเอง และห้ามทำรายการกับ
บัญชีที่สูงกว่าตัวเอง** ถ้าไม่มีกฎนี้ เจ้าหน้าที่สร้างบัญชี `admin` ให้ตัวเองได้ในสองคลิก
แล้วเส้นแบ่งบทบาททั้งหมดก็ไม่มีความหมาย

ไม่มีใครทำกับบัญชีตัวเองได้นอกจากแก้ชื่อ: ปิดบัญชีตัวเองคือการเตะตัวเองออกกลางการกด
ลดบทบาทตัวเองคือการล็อกตัวเองออกจากปุ่มของ admin และการตั้งรหัสผ่านตัวเองทางนี้คือการ
เปลี่ยนรหัสโดยไม่ต้องรู้รหัสเดิม (ใช้ปุ่มกุญแจบนหัวหน้าจอแทน ซึ่งถามรหัสเดิมก่อน)

**ไม่มีการลบบัญชี** ทั้งบนเว็บและใน CLI "ลบ" ในหน้าจอคือ **ปิดบัญชี** ซึ่งตัดทุกเครื่องของ
คนนั้นทันที ชื่อผู้ใช้ถูกจองตลอดไปเพราะมันอยู่ในบันทึกว่าใครทำอะไร

เพราะฉะนั้นอย่าคิดว่าบทบาทคือยศหรือความอาวุโส มันคือคำตอบของคำถามว่า **ใครควรล้างงานทั้งปี
ได้ในคลิกเดียว และใครควรตัดสินว่าใครเข้าระบบได้**

**การจัดการบัญชีทำได้สองทาง** ในโปรแกรมที่แท็บ **จัดการผู้ใช้งาน** (ต้องล็อกอินก่อน) และที่
เครื่องเซิร์ฟเวอร์ด้วย `manage_users.py` สองทางนี้อ่านกฎชุดเดียวกันและเขียนตารางเดียวกัน
ต่างกันที่ CLI **ไม่ตรวจอันดับบทบาท** เพราะคนที่นั่งหน้าเครื่องนั้นอยู่นอกระบบบทบาทโดยนิยาม
(ADR 0004) และมันคือทางกลับทางเดียวตอนที่บัญชีผู้ดูแลระบบทุกบัญชีเข้าไม่ได้พร้อมกัน

**บัญชีแรกยังสร้างได้ที่เครื่องเซิร์ฟเวอร์เท่านั้น** แท็บอยู่หลังด่านล็อกอิน มันจึงสร้างบัญชี
แรกไม่ได้ตามนิยาม และหน้าสร้างบัญชีที่ไม่ต้องล็อกอินคือรูที่ ADR 0004 ปฏิเสธไว้

| แนวทาง | เหตุผล |
|---|---|
| ทุกคนเป็น `staff` เป็นค่าเริ่มต้น | `add` ให้ staff อยู่แล้ว ต้องตั้งใจพิมพ์ `--role admin` เท่านั้นถึงจะได้ admin |
| ให้ `admin` **2 คน** | 1 คน = วันที่เขาลาหรือย้าย ไม่มีใครล้างระบบได้ตอนขึ้นรอบประเมินใหม่ / ทุกคน = ปุ่มนั้นอยู่บนจอของทุกคนตลอดเวลา มีกล่อง confirm กั้นชั้นเดียว |
| ให้คนที่**รับผิดชอบข้อมูล** ไม่ใช่คนที่ตำแหน่งสูงสุด | ปุ่มนั้นใช้จริงปีละครั้งตอนขึ้นรอบใหม่ คนที่ควรกดคือคนที่รู้ว่ารอบเก่าถูกเก็บครบแล้ว |
| ตั้งชื่อผู้ใช้ให้สาวกลับถึงตัวคนได้ เช่น `nipaporn.k` | ชื่อไปอยู่ในบันทึกว่าใครลบอะไร และ**ถูกจองตลอดไป** ชื่อตามตำแหน่งอย่าง `hr1` ทำให้บันทึกเก่าชี้ไปที่คนสองคนเมื่อมีการย้ายงาน |
| คนย้าย/ลาออก → `disable` ทันที | ตัดทุกเครื่องของเขาออกเดี๋ยวนั้น ถ้ารอให้หมดอายุเอง คนที่เคยติ๊ก "จำฉันไว้" ยังเข้าได้อีก 30 วัน |
| ต้นรอบประเมินทุกครั้ง รัน `list` หนึ่งที | ดูว่าเหลือใครอยู่ ใครค้างล็อกอินกี่เครื่อง บัญชีที่ไม่มีใครใช้แล้วให้ `disable` |

**ยังไม่มีบทบาทอ่านอย่างเดียว** ถ้ามีหัวหน้าที่ต้องเข้ามาดูผลประเมินแต่ไม่ควรแก้ ตอนนี้มี
ทางเลือกแค่ให้ `staff` (ซึ่งลบรายการทีละอันได้) หรือไม่ให้บัญชีเลย — การเพิ่ม `viewer`
ต้องสร้างตาราง `users` ใหม่แล้วย้ายข้อมูล เพราะ `role` มี `CHECK` อยู่ใน schema และ SQLite
แก้ `CHECK` ด้วย `ALTER` ไม่ได้ (บันทึกไว้ใน [spec.md](spec.md))

## โหมดการทำงาน

หน้าเว็บตรวจเองตอนเปิดว่าคุยกับ Flask ได้หรือไม่ แล้วแสดงสถานะที่ badge มุมขวาบน

| โหมด | เงื่อนไข | ข้อมูลเก็บที่ | ไฟล์แนบ |
|---|---|---|---|
| **Flask + SQLite** | รันผ่าน `python app.py` หรือ `.exe` | `hr_promotion.db` | ใช้งานได้ครบ |
| **LocalStorage (Offline)** | เปิดไฟล์ HTML ตรง ๆ โดยไม่มี backend | LocalStorage ของเบราว์เซอร์ | **ไม่รองรับ** |

โหมด LocalStorage มีไว้เป็นทางหนีทีไล่เท่านั้น การใช้งานจริงควรใช้โหมด Flask

## ข้อมูลและไฟล์

| สิ่งที่เก็บ | ที่อยู่ |
|---|---|
| ฐานข้อมูล | `hr_promotion.db` (SQLite, โหมด WAL) อยู่ข้างตัว `app.py` หรือข้างตัว `.exe` |
| ไฟล์ PDF ที่อัปโหลด | `static/uploads/<uuid>.pdf` — ชื่อไฟล์บนดิสก์เป็น UUID ชื่อจริงเก็บใน DB |

**การสำรองข้อมูล** คัดลอก `hr_promotion.db` พร้อมโฟลเดอร์ `static/uploads/` ไปทั้งคู่
ทั้งสองอย่างต้องไปด้วยกัน เพราะ DB เก็บแค่ชื่อไฟล์ ไม่ได้เก็บตัวไฟล์

ฟิลด์ที่ server บังคับว่าต้องกรอก: ชื่อ, นามสกุล, ตำแหน่งปัจจุบัน, ตำแหน่งเลขที่
(ฟอร์มฝั่งหน้าเว็บบังคับมากกว่านี้)

## เงื่อนไขการอัปโหลดไฟล์

server ตรวจทุกไฟล์ก่อนเขียนลงดิสก์ — ไม่เชื่อการตรวจฝั่งหน้าเว็บ เพราะยิง API ตรงข้ามด่านนั้นได้

| เงื่อนไข | ถ้าไม่ผ่าน |
|---|---|
| ต้องไม่เป็นไฟล์ว่าง | `400` |
| ต้องมี header `%PDF-` ใน 1024 ไบต์แรก | `400` |
| ขนาดไม่เกิน 100 MB | `413` |
| ต้องมี record นั้นอยู่จริง | `404` |

อัปโหลดซ้ำช่องเดิมเป็นการ **แทนที่** ไฟล์เก่า (1 รายการมีไฟล์ได้ช่องละ 1 ไฟล์)

## API

ทุก endpoint ตอบเป็น JSON ภาษาไทยอ่านออกตรง ๆ (ไม่ escape เป็น `\uXXXX`)

**ทุก endpoint ต้องมีเซสชัน** ถ้าไม่มีจะได้ `401` พร้อมข้อความ ไม่ใช่รายการว่าง เครื่องมือ
อย่าง curl ล็อกอินด้วยกลไกเดียวกัน ไม่มี API key แยก:

```bash
curl -c jar -X POST http://127.0.0.1:5000/login -d "username=somchai&password=..."
curl -b jar http://127.0.0.1:5000/api/records
```

| Method | URL | ทำอะไร |
|---|---|---|
| GET/POST | `/login` | หน้าล็อกอิน / ตรวจรหัสผ่าน (เข้าได้โดยไม่ต้องล็อกอิน) |
| POST | `/logout` | ออกจากระบบ (ลบเซสชันจริง ไม่ใช่แค่ลืม cookie) |
| GET/POST | `/change-password` | เปลี่ยนรหัสผ่านของตัวเอง |
| GET | `/api/records` | รายการทั้งหมด (ใหม่สุดก่อน) |
| GET | `/api/records/<id>` | รายการเดียว |
| POST | `/api/records` | สร้างรายการใหม่ |
| PUT | `/api/records/<id>` | แก้ไขรายการ (ทับทุกคอลัมน์) |
| DELETE | `/api/records/<id>` | ลบรายการ + ไฟล์แนบทั้งหมด |
| DELETE | `/api/records` | ลบทั้งระบบ — **เฉพาะ admin** (staff ได้ 403) |
| GET | `/api/records/<id>/attachments` | รายการไฟล์แนบ (metadata) |
| POST | `/api/records/<id>/attachments` | อัปโหลด PDF (multipart หรือ base64-in-JSON) |
| GET | `/api/attachments/<att_id>` | ดาวน์โหลดไฟล์ |
| GET | `/api/attachments/<att_id>/preview` | เปิดดูไฟล์ในเบราว์เซอร์ |
| DELETE | `/api/attachments/<att_id>` | ลบไฟล์แนบ |
| GET | `/api/stats` | ยอดรวมแยกตามผลการประเมินและระดับตำแหน่ง |
| GET | `/api/export/csv` | export CSV (UTF-8 BOM) |

รายละเอียด schema และหมายเหตุสำหรับคนที่จะแก้โค้ดอยู่ใน [CLAUDE.md](CLAUDE.md)

## ความปลอดภัยที่ควรรู้

- **ทุกหน้าและทุก API ต้องล็อกอิน** ไม่มีข้อยกเว้นแม้แต่เครื่องที่รันโปรแกรมเอง รหัสผ่านเก็บเป็น
  แฮช scrypt ไม่ได้เก็บตัวรหัสจริง กรอกผิดติดกัน 5 ครั้งบัญชีนั้นจะถูกล็อก 5 นาทีแล้วปลดเอง
- **ข้อมูลวิ่งเป็น HTTP ธรรมดา ไม่ได้เข้ารหัส** ถ้าเปิดให้ทั้งวง LAN ด้วย `run_server.bat`
  คนที่ดักจับทราฟฟิกในวงได้จะเห็นรหัสผ่านตอนล็อกอิน เรายอมรับข้อจำกัดนี้โดยรู้ตัว เหตุผลและ
  ทางเลือกที่ไม่เลือกอยู่ใน [docs/adr/0004](docs/adr/0004-the-security-boundary-is-the-office-lan.md)
  — **วันที่จะเปิดระบบนี้ออกอินเทอร์เน็ต ต้องกลับไปอ่านเอกสารนั้นก่อน**
- โหมด debug ปิดเป็นค่าเริ่มต้น เปิดได้ด้วย `HR_DEBUG=1` **สำหรับตอนพัฒนาเท่านั้น** เพราะ debugger
  ของ Werkzeug รันคำสั่ง Python จากเบราว์เซอร์ได้ และถูกบังคับปิดอัตโนมัติเมื่อเปิดให้เครื่องอื่นเข้าถึง
- ไฟล์ `hr_promotion.db` และไฟล์ใน `static/uploads/` ไม่ได้เข้ารหัส และถูกตั้งไม่ให้ commit ขึ้น git
  (ดู `.gitignore`) ใครที่เข้าถึงเครื่องเซิร์ฟเวอร์ได้โดยตรง อ่านข้อมูลทั้งหมดได้โดยไม่ต้องผ่านหน้าล็อกอิน
- บันทึกว่าใครเพิ่ม แก้ หรือลบอะไร อยู่ในไฟล์ `hr_promotion.log` บนเครื่องเซิร์ฟเวอร์ ไม่มีหน้าจอให้ดู
  และไฟล์จะหมุนทิ้งเมื่อโตเกิน 1 MB (เก็บย้อนหลัง 3 ไฟล์)
